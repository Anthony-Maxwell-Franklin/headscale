### Current Behavior

If I:

1) Change an OIDC user's email "username" from say user@domain.com to user@new-domain.com
2) Rename the user in Headscale via `headscale user rename -i <id> --new-name user@new-domain.com`
3) Log the user back into Headscale

Then `headscale user list` shows their updated Username and Email (from the OIDC login).
Also `headscale node list --user user@new-domain.com` pulls back their owned nodes.

However `headscale node list` shows their old email (user@domain.com) for the node's "User".   I'm assuming the in-memory map just isn't updated, as restarting Headscale results in the new/correct user (user@new-domain.com).

### Expected Behavior

I'd expect `headscale node list` have updated User information after changes without requiring a restart.

I am pretty sure that the issue is that the email coming from OIDC is not stored in the username field, but in the email field, and we do not expose a way to update this, as OIDC is considered source of truth and not editable. I think it would be accurate to say that we do not have a supported path for migrating users from one OIDC domain to another. 

Per now, I think editing the database (at own risk) would be the approach, but it would be crucial to also get the OIDC unique token right too and this is more complicated than just the email. 

This is potentially something we could look at in the next release, but I suspect it would realistically be something to tackle when we revisit OIDC down the line, and still not guaranteed that we will make it editable.

Sorry, I probably wasn't clear enough, as I think this may be more simple then you're thinking. (or I could be wrong. :) )

Basically yes, the `headscale rename` command does just change the username field -- which is fine.  The email field is actually adjusted automatically the next time the OIDC user logs into Headscale with a new email.  So OIDC _is_ the source of truth for the email field.

So by doing a `headscale rename` and forcing the user to re-login (expire their nodes), we have both the username and email updated properly as `headscale user list` confirms.   However the node info (`node list`) doesn't seem to get its "user" field updated -- at least not until a Headscale restart.   The nodes know they are owned by the new user (ie. `node list --user user@new-domain.com` works) but listing node information still has the old user field info.  

Since a restart of Headscale gets everything into sync, I was assuming it's currently just missing updating that node user field in the in-memory map when the user info is updated.  If that makes sense?
