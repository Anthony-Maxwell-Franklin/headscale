### Current Behavior

This was partly my mistake not using help before typing the command but when using headscale accept-routes command, identifier is given with flag -i but I assumed routes will be an arg given that it's a command about routes. When entering routes with command like `headscale nodes approve-routes -i 2 "0.0.0.0/0,::/0,xxx.xxx.xxx.xxx/32,xxxx:xxxx:xxxx:xxxx::/64"`, it should give out an error instead of giving `Node updated` as output.

### Expected Behavior

Expected output is `headscale nodes approve-routes does not allow arguments`

### Steps To Reproduce

The above example should work.

### Environment

```markdown
- OS: Debian 13
- Headscale version: 0.29.4
```

### Runtime environment
Headscale runs on A public cloud VPS with public IPv4 and IPv6

### Debug information

Not needed in this case.

Created: 2026-10-08T16:52:04Z; updated: 2026-10-08T16:52:04Z

I have a fix ready: `Args: cobra.NoArgs` on `approve-routes` and on the other `nodes` subcommands that take flags only (register, list, list-routes, expire, delete, backfillips, tag), with a test. `headscale nodes approve-routes -i 2 "0.0.0.0/0"` then fails with `unknown command "0.0.0.0/0" for "headscale nodes approve-routes"` instead of printing `Node updated`. Happy to open the PR once vouched.
