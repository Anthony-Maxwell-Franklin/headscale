### Is there an existing issue for this?

- [x] I have searched the existing issues

### Current Behavior

The documentation tells us which endpoints Headscale exposes for "itself" here https://headscale.net/stable/ref/api/#rest-api. 
But it doesn't document the routes used by Tailscale clients / browsers to talk to the control plane, like the page at `/register/<registration_id>`.

### Expected Behavior

The documentation also includes at least the base routes required for the clients to work.

### Steps To Reproduce

1. Go to documentation page https://headscale.net/stable/ref/api/#rest-api.
2. See the endpoint `/register/<registration_id>` is not documented.

### Environment

```markdown
- OS: `Linux <hostname> 6.12.35 #1-NixOS SMP PREEMPT_DYNAMIC Fri Jun 27 10:11:46 UTC 2025 x86_64 GNU/Linux`
- Headscale version: `0.28.0`
- Tailscale version: `1.96.5 (macOS Standalone)`
- Number of nodes: 10
```

### Runtime environment

- [x] Headscale is behind a (reverse) proxy
- [x] Headscale runs in a container

Probably out of scope for this issue.
