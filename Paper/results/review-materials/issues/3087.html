### Current Behavior

We have a section ["Restrict access to exit nodes per user or group"](https://headscale.net/0.28.0/ref/routes/#restrict-access-to-exit-nodes-per-user-or-group) which seems to no longer work in 0.27.0, 0.27.1 and 0.28.0

The policy from the docs:

```json
{
  "hosts": {
    "exit1": "100.64.0.1/32",
    "exit2": "100.64.0.2/32"
  },
  "acls": [
    {
      "action": "accept",
      "src": [
        "alice@"
      ],
      "dst": [
        "exit1:*"
      ]
    }
  ]
}
```

evaluates to the following filter (from `/debug/filter`):

```json
[
  {
    "SrcIPs": [
      "10.64.0.3/32"
    ],
    "DstPorts": [
      {
        "IP": "100.64.0.1/32",
        "Ports": {
          "First": 0,
          "Last": 65535
        }
      },
      {
        "IP": "fd7a:115c:a1e0::1/128",
        "Ports": {
          "First": 0,
          "Last": 65535
        }
      }
    ],
    "IPProto": [
      6,
      17
    ]
  }
]
```

While a [policy with `autogroup:internet:*`](https://headscale.net/0.28.0/ref/routes/#restrict-the-use-of-an-exit-node-with-acl) evaluates to this filter (shortened):

```json
[
  {
    "SrcIPs": [
      "100.64.0.3/32",
      "fd7a:115c:a1e0::3/128"
    ],
    "DstPorts": [
      {
        "IP": "0.0.0.0/5",
        "Ports": {
          "First": 0,
          "Last": 65535
        }
      },
      {
        "IP": "8.0.0.0/7",
        "Ports": {
          "First": 0,
          "Last": 65535
        }
      },
....
```

The client shows available exit nodes with both policies but traffic is only routed in the `autogroup:internet:*` case.

### Expected Behavior

Since this is a Headscale specific workaround and policy related work is planned for this milestone, we should either rewrite this to grants/via (ref: https://tailscale.com/docs/reference/examples/grants#route-traffic-through-exit-nodes-based-on-location) or remove it from the docs.

### Steps To Reproduce

Follow the steps in the docs to run an exit node: https://headscale.net/0.28.0/ref/routes/#exit-node and compare [Restrict the use of an exit node with ACL](https://headscale.net/0.28.0/ref/routes/#restrict-the-use-of-an-exit-node-with-acl) with [Restrict access to exit nodes per user or group](https://headscale.net/0.28.0/ref/routes/#restrict-access-to-exit-nodes-per-user-or-group).

 Can confirm this also affects regular (non-exit-node) ACL rules on v0.28.0.

  Setup: Two nodes — one tagged (tag:gaming, tag:infra), one user-owned. Policy uses groups in `src` and `*:*` in `dst`:

```json
   {
     "groups": {
       "group:home": ["owner@example.com", "user2@example.com"]
     },
     "acls": [
       {"action": "accept", "src": ["group:home"], "dst": ["*:*"]}
     ]
   }
```

  Result: PacketFilter: `[]` — empty filter, all TCP traffic blocked. tailscale ping works (bypasses filter), but real connections (e.g. Minecraft on port 25565) are dropped.

  Replacing `group:home` with `*` in src immediately fixes it:

```json
   {"action": "accept", "src": ["*"], "dst": ["*:*"]}
```
  So the issue isn't limited to exit node restrictions — group-based src rules produce empty filters for any destination when tagged nodes are involved.

  Using `{"src": ["*"], "dst": ["*:*"]}` as a workaround until v0.29.0.

Created: 2026-05-10T07:41:56Z; updated: 2026-05-10T07:41:56Z

Workaround verified: replacing user/group `src` with `src: ["*"]` immediately makes the exit-node flow work end-to-end (`curl https://api.ipify.org` returns the exit node's public IP, ICMP/TCP to arbitrary internet hosts succeeds).

For anyone hitting this with a structured ACL who wants to keep peer-access restrictions and only open the exit-node path, this minimal-permission variant works:

```hujson
"acls": [
  // existing user/group rules KEEP src: ["user@"] / ["group:..."]
  // and KEEP dst restricted to peers (NOT "*:*", NOT autogroup:internet)
  { "action": "accept", "src": ["user@"],        "dst": ["user@:*"] },
  { "action": "accept", "src": ["group:family"], "dst": ["group:family:*"] },

  // ONE additional rule with src: ["*"] just for internet egress via exit nodes
  { "action": "accept", "src": ["*"], "dst": ["autogroup:internet:*"] }
]
```

The trade-off: `src: ["*"]` here grants every tailnet user the right to use any approved exit node. Peer-to-peer access between users stays restricted by the original rules.

Tested combinations that **do not** work (all produce empty effective filter for the user→internet flow when exit nodes are tagged):

- `src: ["user@"], dst: ["autogroup:internet:*"]`
- `src: ["user@"], dst: ["*:*"]`
- `src: ["user@"], dst: ["*:*", "autogroup:internet:*"]`
- `src: ["group:..."], dst: [...]` (any of the above)

The only `src` value that produces a non-empty filter is `["*"]`. So #3087 isn't strictly limited to "Restrict access to exit nodes per user or group" as the title suggests — it's a more general issue with user/group-scoped src against tagged-dst nodes (which exit nodes typically are).
