## Problem description

There are two nodes in a Headscale/Tailscale network:

### `node1` — exit node

```text
Internal IP: 10.1.0.2/24
External IP: 88.88.88.2/24
External subnet: 88.88.88.0/24
```

### `node2` — client

```text
Internal IP: 10.2.0.2/24
```

When `node2` uses `node1` as an exit node, general Internet access works as expected.  
For example, access to external addresses such as `8.8.8.8` works.

However, `node2` cannot access other addresses from the same external subnet that is directly connected to `node1`.

Example:

```bash
# Before enabling node1 as exit node
node2$ ping -c1 88.88.88.3
# OK

node2$ ping -c1 8.8.8.8
# OK

# Enable node1 as exit node
node2$ tailscale up --exit-node=node1 --accept-routes --login-server=https://vpn.example.com

# After enabling node1 as exit node
node2$ ping -c1 88.88.88.3
# FAIL

node2$ ping -c1 8.8.8.8
# Still OK
```

So the problem is not with exit-node forwarding in general.  
The problem appears only for destinations that belong to the external subnet directly connected to the exit node itself, in this example:

```text
88.88.88.0/24
```

## Cause

When `node2` selects `node1` as the exit node, all external IPv4 traffic from `node2` is routed through the Tailscale default route: `0.0.0.0/0`. Therefore, a packet from `node2` to `88.88.88.3` is sent via `tailscale0` and delivered through WireGuard to `node1`.

When Tailscale builds the inbound filter for a node advertising an exit node, it explicitly subtracts locally reachable interface networks of the exit node from the advertised default route.

Relevant code:

`tailscale/ipn/ipnlocal/local.go`, around line `2997`:

```go
if prefs.Valid() {
    if buildfeatures.HasAdvertiseRoutes {
        for _, r := range prefs.AdvertiseRoutes().All() {
            if r.Bits() == 0 {
                // When offering a default route to the world, we
                // filter out locally reachable LANs, so that the
                // default route effectively appears to be a "guest
                // wifi": you get internet access, but to additionally
                // get LAN access the LAN(s) need to be offered
                // explicitly as well.
                localInterfaceRoutes, hostIPs, err := interfaceRoutes()
                if err != nil {
                    b.logf("getting local interface routes: %v", err)
                    continue
                }
                s, err := shrinkDefaultRoute(r, localInterfaceRoutes, hostIPs)
                if err != nil {
                    b.logf("computing default route filter: %v", err)
                    continue
                }
                localNetsB.AddSet(s)
```

On `node1`, the external interface has: `88.88.88.2/24`. Therefore, the whole network is treated as a locally connected network of the exit node.

Inside `shrinkDefaultRoute`, this local interface network is removed from the allowed default route. Then only the host's own IP address, `88.88.88.2`, is added back. But neighbouring addresses from the same subnet, e.g. `88.88.88.3` are not added back. Relevant code:

`tailscale/ipn/ipnlocal/local.go`, around line `3237`:

```go
// shrinkDefaultRoute returns an IPSet representing the IPs in route,
// minus those in removeFromDefaultRoute and localInterfaceRoutes,
// plus the IPs in hostIPs.
func shrinkDefaultRoute(route netip.Prefix, localInterfaceRoutes *netipx.IPSet, hostIPs []netip.Addr) (*netipx.IPSet, error) {
    var b netipx.IPSetBuilder
    // Add the default route.
    b.AddPrefix(route)
    // Remove the local interface routes.
    b.RemoveSet(localInterfaceRoutes)

    // Having removed all the LAN subnets, re-add the hosts's own
    // IPs. It's fine for clients to connect to an exit node's public
    // IP address, just not the attached subnet.
    //
    // Truly forbidden subnets (in removeFromDefaultRoute) will still
    // be stripped back out by the next step.
    for _, ip := range hostIPs {
        if route.Contains(ip) {
            b.Add(ip)
        }
    }

    for _, pfx := range removeFromDefaultRoute {
        b.RemovePrefix(pfx)
    }
    return b.IPSet()
}
```

After the packet is decrypted on `node1`, the inbound filter checks whether the destination address belongs to a network that this node is allowed to receive from Tailscale. For destination `88.88.88.3`, this check fails, because `88.88.88.0/24` was removed from the effective default route and was not explicitly advertised as a subnet route.

As a result, the packet is dropped inside `tailscaled`.

## Proposed workaround / solution that works for us

On the exit node, explicitly advertise the external subnet:

```bash
tailscale up \
  --advertise-exit-node \
  --advertise-routes=88.88.88.0/24
```

However, this route should **not** be approved or enabled in Headscale.

The purpose of advertising this route is not to distribute it as a subnet route to other clients.

The purpose is only to make the local `tailscaled` instance on `node1` treat this subnet as an allowed destination network, so that it does not drop inbound packets received from `node2`.

As long as the route is not approved in Headscale, it will not be distributed to clients as a subnet route.

Therefore, when `node1` is not selected as an exit node, traffic to `88.88.88.0/24` will continue to use the normal Internet route.
