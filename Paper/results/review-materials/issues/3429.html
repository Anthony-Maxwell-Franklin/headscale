### Current Behavior

I observe multiple users can have the same `username` if the users are later created/onboarded via OIDC.

```shell
# headscale users list
ID | Name           | Username  | Email          | Created
1  |                | debtquity |                | 2026-07-02 06:18:07
2  | Darren Rambaud | debtquity | me@example.com | 2026-08-16 03:29:59
3  |                | unused    |                | 2026-08-19 19:24:36
```

No issue observed when logging in and creating user via OIDC. However, after a restart of the headscale process. It prevented headscale from starting up:

```shell
# journalctl -u headscale.service -e
...
Aug 19 19:19:41 ... headscale-start[124195]: Error: initializing: creating new headscale: init state: initializing policy manager: validating policy user references: multiple users found: token "debtquity@" found: [ 1: debtquity, 2: debtquity,  ]
Aug 19 19:19:41 ... systemd[1]: headscale.service: Main process exited, code=exited, status=1/FAILURE
Aug 19 19:19:41 ... systemd[1]: headscale.service: Failed with result 'exit-code'.
Aug 19 19:19:44 ... systemd[1]: Stopped headscale coordination server for Tailscale.
```

Note: attempts to create or rename user via CLI will return an error:

```
# headscale users create debtquity
Error: creating user: rpc error: code = Internal desc = creating user: creating user: constraint failed: UNIQUE constraint failed: users.name (2067)

# headscale users rename -i 3 -r debtquity
Error: renaming user: rpc error: code = Unknown desc = updating user: constraint failed: UNIQUE constraint failed: users.name (2067)
```

### Expected Behavior

Should return unique name constraint error and prevent user from being created until username conflict resolved; or merge the 2 users.

### Steps To Reproduce

1. Create user via `headscale users create USERNAME`
2. Enable OIDC in headscale with `oidc.*` configuration
3. Setup policy file to reference the `USERNAME` in step 1 (if necessary, restart headscale)
```
# policy.path
{
  "groups": {
    "group:network-admin": [
      "USERNAME@"
    ]
  }
}
```
4. In IdP, create a user where the `preferred_username` claim will conflict with the `USERNAME` in step 1
5. Create user via OIDC flow in any tailscale client
6. Restart headscale process

### Environment

```markdown
- OS: NixOS 26.11 (Zokor) [6.18.41, x86_64]
- Headscale version: v0.29.3 (managed w/ `services.headscale` NixOS module)
- Tailscale version: 1.98.10
- Nodes: 12
- OIDC: Pocket ID (v2.13.0)
```
