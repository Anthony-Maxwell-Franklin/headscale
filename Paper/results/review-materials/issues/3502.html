### Current Behavior

A node that advertises exit routes never receives its own updated self node after the routes are approved with `headscale nodes approve-routes`. On the node, `tailscale status --json` keeps `.Self.ExitNodeOption = false` and `.Self.AllowedIPs` without `0.0.0.0/0` and `::/0`, `tailscale status` does not print "offers exit node", and `tailscale debug netmap` shows `SelfNode.Hostinfo.RoutableIPs = ["0.0.0.0/0", "::/0"]` next to `SelfNode.AllowedIPs = ["100.64.0.1/32", "fd7a:115c:a1e0::1/128"]`. Nothing changes over time: the node only learns its approved routes when it opens a new map session (`systemctl restart tailscaled`, `tailscale down && tailscale up`).

Up to v0.29.3, withdrawing and re-advertising the routes on the node (`tailscale set --advertise-exit-node=false && tailscale set --advertise-exit-node`) made headscale send the node its self node, which was a usable workaround. Since v0.29.4 that no longer has any effect: `Self.ExitNodeOption` stays `false` after the toggle too.

With headscale logging at `trace`, both the gRPC approval and each half of the toggle end in `node change processing started node.id=1 reason="policy change"` followed by `update sent` on the node's stream, and the node's self stays unchanged (full log below).

### Expected Behavior

After `headscale nodes approve-routes`, the approved node receives a map response carrying its updated self node, so `Self.AllowedIPs` contains the approved exit routes and `Self.ExitNodeOption` is `true` on its live map session, without restarting tailscaled. Re-advertising the routes should keep refreshing the node's self as it did on v0.29.3.

### Steps To Reproduce

1. headscale v0.29.4, one user, no policy.
2. On a node (tailscale 1.102.4): `tailscale up --login-server https://<headscale> --auth-key <key> --advertise-exit-node`.
3. `headscale nodes approve-routes --identifier <id> --routes 0.0.0.0/0,::/0`.
4. On the node, wait a minute, then `tailscale status --json | jq .Self.ExitNodeOption` → `false`; `tailscale debug netmap | jq '.SelfNode | {AllowedIPs, Hostinfo: {RoutableIPs: .Hostinfo.RoutableIPs}}'` shows the routes announced but absent from `AllowedIPs`.
5. `tailscale set --advertise-exit-node=false && tailscale set --advertise-exit-node`, wait → still `false` (on v0.29.3 this step flips it to `true`).
6. `systemctl restart tailscaled` → `true`.

### Where it comes from (from the v0.29.4 source)

The mapper only adds the self node to a response when the change's `OriginNode` is the receiving node: `isSelfUpdate := r.OriginNode != 0 && r.OriginNode == nodeID` ([`batcher.go:106`](https://github.com/juanfont/headscale/blob/v0.29.4/hscontrol/mapper/batcher.go#L106)), passed as `includeSelf` to `policyChangeResponse` ([`batcher.go:128`](https://github.com/juanfont/headscale/blob/v0.29.4/hscontrol/mapper/batcher.go#L128), [`mapper.go:353-355`](https://github.com/juanfont/headscale/blob/v0.29.4/hscontrol/mapper/mapper.go#L353-L355)).

1. `State.SetApprovedRoutes` always ends with `if routeChange || !c.IsFull() { c = change.PolicyChange() }` ([`state.go:1053-1055`](https://github.com/juanfont/headscale/blob/v0.29.4/hscontrol/state/state.go#L1053-L1055)). `c` is never `IsFull()` there, so the gRPC/CLI approval always fans out a bare `PolicyChange()` with `OriginNode == 0`, and the approved node never gets its self. This part is the same on v0.29.3 and on `main`.
2. Since v0.29.4, `NodeView.HasPolicyChange` also compares `ExitRoutes()` ([`node.go:1233`](https://github.com/juanfont/headscale/blob/v0.29.4/hscontrol/types/node.go#L1233), commit 4411264e, cherry-pick of 905ab92f from #3450, backported in #3467). A node re-advertising its already-approved exit routes therefore makes `PolicyManager.SetNodes` return `true` even when the filter hashes match ([`policy.go:900`](https://github.com/juanfont/headscale/blob/v0.29.4/hscontrol/policy/v2/policy.go#L900), the "all hashes match" line in the trace), `updatePolicyManagerNodes` returns `change.PolicyChange()` ([`state.go:2899`](https://github.com/juanfont/headscale/blob/v0.29.4/hscontrol/state/state.go#L2899)), and `UpdateNodeFromMapRequest` returns it before `buildMapRequestChangeResponse` could produce `change.NodeAdded(id)` with its `OriginNode` ([`state.go:3265-3276`](https://github.com/juanfont/headscale/blob/v0.29.4/hscontrol/state/state.go#L3265-L3276)). On v0.29.3 the same request ended in `NodeAdded(id)` and `selfMapResponse`, which is why the toggle used to work.

From the code, peers are not affected: the policy response still sends them the node with its routes. Only the node's own view is stale, and nothing refreshes it while its map session stays up.

#2978 / #2996 fixed the same omission for tags by setting `c.OriginNode = nodeID` in `SetNodeTags` ([`state.go:1018`](https://github.com/juanfont/headscale/blob/v0.29.4/hscontrol/state/state.go#L1018)). Doing the same for the change returned by `SetApprovedRoutes`, and for the policy change returned from a node's own map request in `UpdateNodeFromMapRequest`, makes the node receive its self node in both cases; I will open a PR. The open draft #3501 rewrites these lines but still returns a bare `PolicyChange()` for an announced route, so it does not change this behaviour.
