## Flaky Tests

Failure rate is approximate, based on ~40 PRs that ran integration tests.

### Critical (~20-42% failure rate)

- [ ] `TestAutoApproveMultiNetwork` (all subtests) — `integration/route_test.go:2037` — ~42% failure rate. ACL/route auto-approve changes don't propagate within EventuallyWithT timeouts on CI runners.
- [ ] `TestACLTagPropagation` — `integration/acl_test.go:2296` — ~20% failure rate. Tag change propagation too slow for CI. Subtests `multiple-tags-partial-removal` and `remove-tag-revokes-access` are worst offenders.

### High (~7-12% failure rate)

- [ ] `TestACLTagPropagationPortSpecific` — `integration/acl_test.go:2852` — ~12%. Port-specific ACL changes via tags don't propagate in time.
- [ ] `TestACLHostsInNetMapTable` — `integration/acl_test.go:101` — ~7%. ACL propagation timing.
- [ ] `TestPingAllByIPManyUpDown` — `integration/general_test.go:1391` — ~7%. Ping failures during up/down cycling.

### Medium (~5% failure rate)

- [ ] `TestOIDCExpiryAfterRestart` — `integration/auth_oidc_test.go:1352`

### Low (~2% failure rate)

- [ ] `TestSubnetRouteACLFiltering` — `integration/route_test.go:2952`

### Unit tests

- [ ] `TestBatcherScalabilityAllToAll` — `hscontrol/mapper/batcher_test.go:580` — Panic: send on closed channel. Race condition in LockFreeBatcher shutdown.
- [ ] `TestAuthenticationFlows` — `hscontrol/auth_test.go:38` — Intermittent 401 from registration cache expiration. (#2935)
- [ ] `TestOIDC024UserCreation` — `integration/auth_oidc_test.go:238` — Non-deterministic DB row ordering. (#2299)

## Common root causes

1. **ACL/tag propagation timing** — Most flakes. EventuallyWithT timeouts too short for CI runners.
2. **Network connectivity races** — Ping timeouts under CI load.
3. **Client startup timeouts** — Tailscale clients don't reach Running state within 2min on slow CI.
4. **Go race conditions** — Actual code bugs (LockFreeBatcher, registration cache).

## Update: PR #3145 (integration test infrastructure standardization)

#3145 addresses several infrastructure issues that contributed to flakiness but
does not fix the core propagation timing issue.

Changes relevant to flaky tests:
- All tests now use embedded DERP + TLS by default (no public DERP dependency)
- Proper CA certificate trust chains (CreateCertificate now returns CA cert
  separately, installed in container trust stores)
- TestACLTagPropagation and TestACLTagPropagationPortSpecific migrated from
  fragile `sleep 3 ; apk add` entrypoints to WithPackages/WithWebserver with
  proper readiness waits
- TestACLPolicyPropagationOverTime was missing embedded DERP/TLS entirely, now
  gets both by default

Observed flake rates across recent PRs (#3130, #3143, #3144, #3134, #3145):
- TestACLTagPropagation: 2/5 PRs (subtests remove-tag-revokes-access and
  multiple-tags-partial-removal)
- TestACLTagPropagationPortSpecific: 1/5 PRs
- TestACLPolicyPropagationOverTime: 1/5 PRs
- TestAuthWebFlowLogoutAndReloginNewUser: 1/5 PRs (ping timeout)

All failures match existing patterns (propagation timeouts, CI resource
contention). The infrastructure fixes should reduce the contributing factors
but the core issue — EventuallyWithT timeouts too short for CI runners on
ACL/tag propagation tests — remains open.
