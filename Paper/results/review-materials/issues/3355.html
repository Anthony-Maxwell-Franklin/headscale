Created: 2026-06-30T17:53:14Z; updated: 2026-06-30T17:53:14Z

This is a regression in what `policy check` does, not a connectivity issue. In 0.28.0 the command validated the file **offline**, with no server and no database:

```go
// v0.28.0 cmd/headscale/cli/policy.go
_, err = policy.NewPolicyManager(policyBytes, nil, views.Slice[types.NodeView]{})
```

Since 0.29 it instead calls a running headscale over the API (`cmd/headscale/cli/policy.go`, `checkPolicy.RunE` → `withClient(... CheckPolicyWithResponse ...)`), which is the socket/`context deadline exceeded` you hit without a server.

The `--bypass-server-and-access-database-directly` flag added after 0.29.1 doesn't cover this case either: `openBypassDB` (`policy.go:42`) prompts interactively (`[y/n]`, so it aborts under CI/closed stdin) and then needs a full config + an existing database — not an offline file check.

Reproduced with the official images, no server and no DB:

```
$ headscale:0.28.0 policy check --file policy.hujson   → Policy is valid        (exit 0)
$ headscale:0.29.1 policy check --file policy.hujson   → context deadline exceeded (exit 1)
```

A `main` build behaves the same: default → API timeout; `--bypass…` → interactive prompt, then `Fatal config error` without a config/DB.

The 0.28 path — a structural parse via `NewPolicyManager(bytes, nil, <empty nodes>)`, needing neither server nor DB — is what CI use needs. Restoring it as a parse-only path is a small change; I can open a PR for it.
